# Distribute the game for offline play

The player should download the game and play offline without a hosted website, as requested on 2026-09-18. This replaces the private web-hosting direction in [ticket #10](https://github.com/zerowing113/data_science_game/issues/10), which now describes downloadable offline packaging. [Ticket #11](https://github.com/zerowing113/data_science_game/issues/11) now covers playtesting the downloaded experience.

The agreed launch experience is download, unzip, double-click Start Game, and play in the player's browser. Support both Windows and macOS. The launcher serves the bundled game locally so the player does not need terminal commands or a Python installation; the downloaded package must support offline play, including first launch. This approach was chosen over directly opening an HTML file because the current module and Python runtime loading depend on a served origin. Initial build targets are Windows 11 x64 and macOS 14+ on Intel and Apple Silicon, with Chrome/Edge as the initial browser targets. Signing, final distribution access, and consumer release verification remain unresolved; updates use replacement downloads.

Automatically save code, experiments, and mission progress locally and resume on reopening, with an explicit Start over option. This accepted requirement is tracked separately in [ticket #12](https://github.com/zerowing113/data_science_game/issues/12); the storage mechanism and behavior across game updates remain to be specified. Preserve revealed final-challenge state so restarting cannot present known answers as an unseen attempt.

The owner explicitly selected an unsigned test release first. Signing/notarization is deferred from the preview; the normal OS security-prompt and launch experience still needs verification.

The implementation uses a native Go launcher with the production web application and Python runtime embedded in its executable. It serves a fixed loopback origin and opens the default browser. External font loading has been removed in favor of local system fonts. Windows x64 and macOS Intel/Apple Silicon ZIP packaging is implemented; unsigned test artifacts and automated verification do not establish signed consumer-release readiness or save/resume acceptance.
